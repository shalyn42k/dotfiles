## 2. SDDM: остаётся ровно две сессии (1 минута)

```bash
sudo rm -f /usr/share/wayland-sessions/{hyprland,hyprland-ilyamiro,hyprland-lua,hyprland-uwsm}.desktop

printf 'NoExtract   = usr/share/wayland-sessions/hyprland.desktop\nNoExtract   = usr/share/wayland-sessions/hyprland-uwsm.desktop\n' | sudo tee -a /etc/pacman.conf
```

Проверка:

```bash
ls -1 /usr/share/wayland-sessions/
```

Ожидается ровно два файла: `hyprland-rig.desktop` и `plasma.desktop`.

Вторая команда обязательна: `hyprland.desktop` и `hyprland-uwsm.desktop`
принадлежат пакету `hyprland` и вернутся при первом же его обновлении — молча,
без `.pacnew`, потому что это `/usr/share`, а не `/etc`.

## 4. Первый вход в serpantinum

```bash
bin/dotprofile switch serpantinum --links-only
```

`--links-only` переставляет симлинки и НЕ пытается горячий свитч. Затем
релогин через SDDM в сессию **«Hyprland (rig)»** — она читает
`profiles/active`, поэтому приземлишься в serpantinum.

**Что смотреть сразу после входа:**

```bash
hyprctl systeminfo | grep configProvider   # ожидается: lua
pgrep -f 'quickshell -p.*serpantinu[m]'    # шелл рига жив
bin/dotprofile doctor                       # битых симлинков нет
```

Шелл на логине поднимается двумя независимыми путями, чтобы не зависеть от
одного: `hyprland.lua` рига стартует `serpantinumd` по абсолютному пути, и
плюс к тому его бинари симлинкнуты в `~/.local/bin`, так что штатный
`config/autostart` апстрима тоже находит их. Двойного старта не будет —
демон держит `/tmp/serpantinumd.pid`. Это была реальная дыра: на логине
`session.sh` не вызывается вовсе (`--links-only` возвращается раньше), а
апстрим звал `serpantinumd` голым именем, которого нет в PATH — риг поднялся
бы без бара.

**Если экран пустой или шелл не поднялся** — аварийный выход есть, `SUPER+F1`
это локскрин, а не выход. Переключись в TTY (`Ctrl+Alt+F2`), залогинься и:

```bash
~/dotfiles/bin/dotprofile switch caelestia --links-only
```

Затем `Ctrl+Alt+F1` обратно и релогин. Это возвращает рабочий риг.

## 5. Бинды serpantinum

Проверить руками, что комбо контракта живут:

| Комба | Ожидание |
| :--- | :--- |
| `SUPER+SHIFT+D` | открывается свитчер ригов |
| `SHIFT+TAB` | лаунчер serpantinum |
| `SUPER+Q` | закрыть окно |
| `SUPER+I/J/K/L` | фокус вверх/влево/вниз/вправо |
| `SUPER+ALT+I/J/K/L` | ресайз окна |
| `SUPER+1..0` | воркспейсы |
| `SUPER+S` | скретчпад |
| `SUPER+Z/X/C/V` | feishin / vesktop / obsidian / AyuGram |
| `CTRL+J` / `CTRL+L` | цикл спец-воркспейсов |
| `ALT+Q` / `ALT+TAB` | группа: тоггл / следующее |
| `SUPER+TAB` | терминал (foot) |
| `SUPER+W` | браузер (zen-browser) |
| `SUPER+R` | редактор (codium) |
| `SUPER+E` | файлы (thunar) |
| `SUPER+T` | hyprkcs |
| `SUPER+G` | gamemode: клавиши лочатся, громкость живёт; выход тем же `SUPER+G` |
| `SHIFT+drag` / `CTRL+drag` | двигать / ресайзить окно мышью |

Три из них апстрим занимал под своё: `SUPER+E` открывал nautilus, `SUPER+R`
перезагружал шелл, `SUPER+W` тоггл обои. Перевешены на контрактное — это тот
самый случай «клавиша есть, но делает не то», который пальцами и ловится.
Функции рига не потерялись: обои остались на `SUPER+Y`, рестарт шелла на
`SUPER+M`.

Счётчик, если что-то не так:

```bash
hyprctl binds -j | jq length     # ожидается около 99
```

`SUPER+Z/X/C/V` матчат приложения по классу окна. Класс `feishin` сверен с
правилами caelestia, остальные — рабочие строки оттуда же, но именно эти
четыре бинда единственные, чьи значения не проверялись в живой сессии
serpantinum. Если приложение запускается вторым экземпляром вместо
переключения — класс другой, скажи мне какой:

```bash
hyprctl clients | grep -i class
```

## 6. Главный критерий: свитч без релогина

Из serpantinum:

```bash
bin/dotprofile switch caelestia
```

Ожидается: печатаются стадии, бар меняется на caelestia, цвета и правила окон
становятся caelestia — **и сессия не завершается**. Обратно:

```bash
bin/dotprofile switch serpantinum
```

Это то, ради чего делалась вся работа. Если сработало — пара
caelestia ↔ serpantinum однодвижковая, и tech-debt п.2 закрыт.

**Чего в этом свитче НЕ будет:** бинды не переключатся. Стадия `binds`
отключена намеренно — снос набора через хендлы роняет композитор (два
SIGSEGV 2026-09-02, оба `CLuaKeybind::push`). Клавиши приезжают релогином.
Путь к починке описан в `docs/tech-debt.md` п.8: снимать через
`hl.unbind(комба)` вместо хендлов, и проверять в отдельном headless-инстансе
Hyprland, а не в рабочей сессии.

## 7. Свитчер: как он теперь выглядит

Переходы читают реальные стадии из `dotprofile`, а не отсчитывают таймер.
Смотреть: собирается ли риг по частям, различается ли анимация в зависимости
от того, с какого рига на какой, честно ли показывается релогин при
переключении в ilyamiro.

Оверлей — единственная часть, которую я не мог проверить вообще никак: QML
рендерится только в живой сессии. Если что-то выглядит криво, скажи что
именно, это правится быстро.
