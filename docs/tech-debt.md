## 1. Два источника правды на один конфиг (главное)

Одни и те же настройки описаны дважды, на двух языках, и синхронизируются
руками:

| Смысл | Источник (caelestia, lua) | Ручной порт (ilyamiro, hyprlang) |
| :--- | :--- | :--- |
| Правила окон | `profiles/caelestia/hypr/hyprland/rules.lua` | `.config/hypr-shared/rules-ilyamiro.conf` |
| Анимации | `profiles/caelestia/hypr/hyprland/animations.lua` | `profiles/caelestia/animations-runtime.keywords` |
| Бинды-свитчер | `.config/caelestia/hypr-user.lua` | `.config/hypr-shared/binds.conf` |
| Настройки WM | `hyprland/{input,misc,gestures,env,execs}.lua` | `.config/hypr-shared/settings-ilyamiro.conf` |

**Это не теория — копии уже разошлись.** Из четырёх багов аудита два были
ровно этим:

- в `animations-runtime.keywords` не доехал `fadeIn` → в hyprlang-сессии
  возвращалась вспышка первого кадра электронов, которую фиксили отдельным
  коммитом;
- правило «одно окно → `gapsout` 20» скопировали в риг, где база `gaps_out`
  не 40, а 4 — и оно работало наоборот, ужимая окно вместо расширения.

Дальше будет так же: правишь `rules.lua`, забываешь `rules-ilyamiro.conf`,
они молча расходятся. Тестов на это нет и быть не может.

**Варианты решения**

1. **Убрать горячий свитч** (см. п.2) — тогда порты не нужны вообще, каждый
   риг живёт со своим родным конфигом. Самое радикальное и самое чистое.
2. **Генератор**: держать один источник (yaml/lua-таблица), из него рендерить
   и `.lua`, и `.conf`. Убирает расхождение, но добавляет сборочный шаг в
   dotfiles — то, чего тут пока сознательно нет.
3. **Смириться и проверять руками**: завести чеклист «поправил в lua —
   поправь в conf». Работает ровно до первого раза, когда забудешь.

## 2. Горячий свитч ригов — источник половины сложности

Hyprland выбирает конфиг-движок (lua или hyprlang) **один раз, при старте**,
и на лету его не меняет. Переключение рига внутри живой сессии — обход этого
ограничения, и он оплачен:

- `bin/rigdo` — определение провайдера в каждом действии;
- `bin/hypr-exec` — потому что `dispatch exec` не работает под lua;
- `animations-runtime.{lua,keywords}` — переводы анимаций на оба движка;
- `disable_autoreload` в `dotprofile`, `safe_reload` в `settings_watcher.sh`;
- сломанный `hyprctl reload` (см. п.3).

При этом бинды и настройки WM при кросс-движковом свитче **всё равно
применяются только после релогина** — `dotprofile` сам это печатает. То есть
хот-свитч даёт неполный результат за высокую цену.

Две SDDM-сессии (`sddm/hyprland-*.desktop`) уже есть и делают то же самое
честно. Если признать релогин единственным способом сменить риг, из репо
уходят все пункты списка выше и весь п.1.

**Оговорка:** с приходом end-4 (тоже lua, см. п.7) свитч caelestia ↔ end4
становится однодвижковым и работает по-настоящему. Так что решение «снести
хот-свитч» стоит принимать не раньше, чем станет ясно, каким набором ригов
реально пользуешься.

## 3. `hyprctl reload` падает после кросс-движкового свитча

`~/.config/hypr` — симлинк на `profiles/active/hypr`. Запущенная сессия
помнит путь своего конфига (`~/.config/hypr/hyprland.lua` для lua-рига).
После переключения `active` на риг с другим движком по этому пути нужного
файла больше нет, и любая перечитка конфига даёт:

```
cannot open ~/.config/hypr/hyprland.lua: No such file or directory
```

Не фатально: сессия продолжает работать со старым конфигом. Но Hyprland
рисует поверх экрана плашку об ошибке конфига (`debug.error_position`).

Сейчас закрыто частично: `dotprofile` гасит автоперечитку
(`disable_autoreload`), `settings_watcher.sh` имеет `safe_reload` с проверкой
провайдера. **Не закрыто:** кнопка reload в панели настроек quickshell
ilyamiro (`profiles/ilyamiro/hypr/settings.json` → `scripts/reload.sh`) —
проверки провайдера там нет.

**Настоящее лечение:** запускать Hyprland с явным путём конфига конкретного
профиля (`Hyprland -c ~/dotfiles/profiles/<rig>/hypr/hyprland.lua`), а не
через симлинк `active`. Тогда сессия всегда знает свой реальный конфиг, что
бы ни делал симлинк, и reload работает всегда. Требует правки
`bin/start-hyprland-profile` и SDDM-сессий; проверить, что относительные
пути внутри конфигов при этом не разъезжаются.

- Кривые `emphasizedDecel` и `specialWorkSwitch` в `animations.lua` — с

## 5. Асимметрии между ригами

- **Правый Shift не работает** в портированном наборе ilyamiro: его бинды
  используют `$mainMod SHIFT_L`, тогда как в caelestia `SUPER + SHIFT` ловит
  оба шифта. `SUPER+RShift+3` в его риге просто молчит.
- `misc.background_color` задан только в caelestia — на ilyamiro при свайпе
  воркспейсов из-под окон видно дефолтный фон, а не цвет схемы.
- `profiles/ilyamiro/hypr/config/env.conf` ставит `__GL_VRR_ALLOWED=0`, пока
  `.config/hypr-shared/settings-ilyamiro.conf` включает `misc:vrr = 1`.
  Противоречие; разобраться, что из этого нужно на самом деле.

## 6. Мелочи

- Бинд свитчера по-прежнему описан в двух форматах: `.config/hypr-shared/binds.conf`
  (hyprlang, для ilyamiro) и `.config/hypr-shared/contract-binds.lua` (lua, для
  hyprkcs-ригов) — `hyprkcs` не умеет `source=` для hyprlang-файлов. Но каждый
  формат теперь в ОДНОМ экземпляре: копия в `.config/caelestia/hypr-user.lua`
  убрана 2026-09-02. Дубль уйдёт совсем вместе с ilyamiro.
- Гапсы caelestia: `gaps_out 40` при `gaps_in 10` → до края экрана 40, между
  окнами 20 (`gaps_in` считается с обеих сторон). Для равномерности
  `gaps_out` должен быть 20. Это дефолт caelestia, так что вопрос вкуса, а не
  баг.

## 7. end-4 как третий риг — почему он будет проще ilyamiro (ЗАКРЫТО: риг удалён 2026-09-02)

Проверено по репозиторию (2026-07-14): `dots/.config/hypr/` содержит
**`hyprland.lua`**, `hyprland.conf` отсутствует. end-4 уехал на lua-провайдер,
как caelestia. Пользовательские оверрайды — `custom/*.lua`, подключаются через
`require()` **после** дефолтов, то есть это официальный механизм, переживающий
апдейты (аналог нашего `hypr-user.lua`).

Следствия:

- caelestia ↔ end4 — **однодвижковый** свитч: путь `~/.config/hypr/hyprland.lua`
  после смены `active` резолвится в конфиг нового рига, `hyprctl reload`
  отрабатывает по-настоящему. Ни переводов правил, ни `animations-runtime.keywords`,
  ни возни с `disable_autoreload` не нужно. Остаётся одна оговорка: `require()`
  кеширует lua-модули, поэтому reload может не подхватить изменения внутри уже
  загруженных модулей — проверить на месте.
- end4 ↔ ilyamiro — по-прежнему кросс-движковый, со всеми оговорками п.2–3.
- Наши бинды кладутся в его `custom/` — не в его файлы, апдейты их не съедят.

Полный план: `docs/specs/2026-07-14-end4-rig-plan.md`.

## 8. Бинды не переключаются при горячем свитче (частично закрыт, стадия отключена)

Найдено 2026-09-02 при проверке «что реально меняется при свитче».

`cmd_switch` в горячей (одномувижковой) ветке применяет три вещи:
`apply_rig_colors`, `apply_rig_animations`, `apply_rig_rules`. **Биндов среди
них нет.** То есть при свитче caelestia ↔ end4 без релогина цвета, анимации и
правила окон становятся целевого рига, а клавиши остаются прежними — до
релогина ты сидишь в новом риге со старыми биндами.

`dotprofile` про это честно печатает («бинды применятся после релогина»), так
что это не тихая поломка, но и не то, что обещает горячий свитч.

**Что нужно для починки.** Механика та же, что у анимаций и правил: chunk
`binds-runtime.lua` на риг + `hyprctl eval "dofile(...)"`. Разница в том, что
`hl.bind` только добавляет — старые бинды чужого рига будут висеть и стрелять.
Нужен снос предыдущего набора.

`hl.unbind(key)` в API есть — проверено на Hyprland 0.56.2,
`/usr/share/hypr/stubs/hl.meta.lua:860`. Значит реализуемо: `apply_rig_binds`
получает старый и новый риг, дофайлит unbind-чанк старого, затем bind-чанк
нового. Unbind-списки генерируются из существующих `keybinds.lua` механически.

**Оговорка.** Не путать с `docs/superpowers/specs/2026-07-18-unified-keybinds-variants.md`
— там про то, *какими должны быть* бинды (три варианта, раздел «Открытое» не
закрыт). Здесь — про то, что *текущие* бинды не следуют за ригом. Второе
чинится независимо от первого и первое не ждёт.

**Статус 2026-09-02.** Реестр владения написан и работает на загрузке конфига
(`.config/hypr-shared/rigbinds.lua`, тесты в `tests/`), контракт §2 сведён в один
файл `.config/hypr-shared/contract-binds.lua` под владельцем `shared`. Но стадия
`binds` в `cmd_switch` **отключена**: снос набора через хендлы роняет композитор.

Два SIGSEGV подряд, оба с одной подписью:

```
Config::Lua::Objects::CLuaKeybind::push(lua_State*, CSharedPointer<SKeybind>)
  ← Config::Lua::CConfigManager::guardedPCall ← ::eval
```

Падает не снятие само по себе — одиночный `:remove()` в зонде отработал чисто
(100 → 99). Падает первый `hl.bind` ПОСЛЕ массового сноса: `push` разыменовывает
уже недействительный `SKeybind`. То есть `__rig.drop` оставляет внутренний
список биндов Hyprland 0.56.2 в состоянии, где очередной bind сегфолтит.
`pcall` не спасает — это падение процесса, а не lua-ошибка.

**Путь к починке:** снимать через `hl.unbind(комба)` вместо хендлов; реестр уже
хранит строку комбы рядом с хендлом. Косвенных подтверждений безопасности
`unbind` три: зонд (unbind, следом 88 биндов, без падения), многолетняя практика
удалённого рига end4 (13 `unbind`, следом 85 биндов) и сам `contract-binds.lua`.
Проверять — в ОТДЕЛЬНОМ headless-инстансе Hyprland, не в живой сессии: два
крэша выше случились именно потому, что проверка шла на рабочем десктопе.

## 9. `CONTESTED` линкует безусловно (ЗАКРЫТО)

`ensure_links` ставит симлинк для каждого каталога из `CONTESTED` не проверяя,
есть ли он у активного рига. Если нет — в `~/.config` остаётся битый симлинк,
и всё, что туда пишет, тихо падает.

Один раз уже выстрелило: у ныне удалённого рига end4 не было `gtk-4.0`, при этом
его matugen рендерил туда `gtk.css` — GTK4-тема не применялась вообще.

**ЗАКРЫТО 2026-09-02.** `ensure_links` теперь линкует `CONTESTED` по наличию, а
отсутствие обязательного каталога — громкая ошибка стадии `links`, не молчание.
Плюс появился `dotprofile doctor`: проверяет, что у каждого рига есть все
обязательные каталоги и что в `~/.config` нет битых симлинков.

## 10. Пакетные SDDM-записи возвращаются при обновлении hyprland

Пакет `hyprland` кладёт в `/usr/share/wayland-sessions/` две свои записи:
`hyprland.desktop` (голый `Exec=Hyprland`) и `hyprland-uwsm.desktop`
(`uwsm start`, при том что `uwsm` мы не ставим — сессия нерабочая).

Обе запускают композитор **в обход** `start-hyprland-profile`: `ensure_links`
не отрабатывает, симлинки `~/.config/*` остаются от прежнего рига.

Удаление не вечное: файлы принадлежат пакету, и любое обновление `hyprland`
положит их обратно (это `/usr/share`, не `/etc` — pacman перезапишет молча,
без `.pacnew`). Правка самих файлов бессмысленна по той же причине.

**Решение 2026-09-02.** Цель — ровно две записи в греетере: наша
«Hyprland (rig)» и `plasma` как запасное DE. Голая `hyprland.desktop` раньше
оставалась аварийным входом, но она молча стартует композитор с симлинками от
прежнего рига, то есть «аварийный вход» приводит в риг, которого ты не
выбирал. Аварийный путь честнее делать из TTY.

`bootstrap.sh` теперь удаляет обе пакетные записи И прописывает `NoExtract` в
`/etc/pacman.conf`:

```
NoExtract   = usr/share/wayland-sessions/hyprland.desktop
NoExtract   = usr/share/wayland-sessions/hyprland-uwsm.desktop
```

Это единственная правка системного конфига, которую делает bootstrap, — она
идемпотентна (строка добавляется, только если её ещё нет).

Если запись всё же вернулась (обновление прошло до появления `NoExtract`) —
перезапустить `bootstrap.sh` либо удалить файл руками.

## 11. Локальный патч в сабмодуле serpantinum

Кнопка «Update» в его гайде (`src/quickshell/guide/AboutTab.qml`) у апстрима
пайпила `install/install.sh` прямо в `eval`. Этот инсталлер делает
`sudo pacman -Syyu --noconfirm` и раскладывает свой конфиг поверх
существующего — а существующий здесь и есть риг, живущий симлинками из
`profiles/active`.

Кнопка перевешена на открытие страницы релизов. Это ЕДИНСТВЕННАЯ наша правка
внутри сабмодуля, и она не переживёт смену пина: `git checkout <новый sha>`
вернёт апстримовский обработчик. При каждом обновлении рига патч надо
накладывать заново — прецедент тот же, что с `shell.qml` у caelestia.

Обновление рига делается осознанно:

```
git -C profiles/serpantinum/shell fetch origin
git -C profiles/serpantinum/shell checkout <sha>
git add profiles/serpantinum/shell && git commit
```

Долг здесь в том, что патч держится на дисциплине. Варианты закрытия: держать
его отдельным `.patch` в профиле и накатывать скриптом после смены пина, либо
форкнуть апстрим и вендорить форк.
