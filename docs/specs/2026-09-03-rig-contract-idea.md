# Идея: свитчер как самостоятельный проект, риг — просто каталог

Дата: 2026-09-03. Статус: **идея, не спека**. Записана, чтобы не потерялась;
до реализации нужен разбор и решение.

## Куда хочется прийти

Свитчер ригов — отдельный проект, а не часть этих дотфайлов. Пользователь
указывает ему ссылку на каталог рига, и дальше всё работает само: свитчер сам
находит риг, знает, чем его запустить, откуда взять палитру и логотип, и как
переключиться.

То есть свитчер не должен знать **ни одного имени рига**.

## Почему сейчас так нельзя

Знание о ригах размазано по коду. Замер 2026-09-03 — имена ригов захардкожены
в восьми местах:

| Файл | Упоминаний |
| :--- | :--- |
| `bin/rigdo` | 27 |
| `bin/kbd-theme-sync` | 13 |
| `Palettes.qml`, `scan-rigs.sh`, `bin/dotprofile` | по 4 |
| `RigIdentity.qml`, `bin/rig-theme`, systemd-юниты | по 1–2 |

`rigdo` не «ссылается на каталог рига» — он содержит рига внутри себя: знает,
что лаунчер у одного зовётся `caelestia shell drawers toggle launcher`, а у
другого `serpantinum msg toggle launcher`. Добавить третий риг сегодня значит
пройти восемь файлов и в каждом дописать ветку.

Частично нужное уже есть: `scan-rigs.sh` находит риги перебором `profiles/*/`.
Но и ему приходится знать, где у кого лежат обои.

## Предлагаемая форма: соглашение, а не конфиг

Риг описывает себя **структурой каталога**. Никакого формата и парсера.

```
<каталог рига>/
  role                    # строка: work | daily | third
  session.sh              # контракт start|stop — единственный обязательный исполняемый
  actions/                # по файлу на действие контракта (KEYBINDS.md §2.1)
    launcher              #   исполняемый; чего нет — того у рига нет
    lock
    screenshot
    shell                 #   рестарт шелла рига
    …
  theme/
    palette.json          # симлинк на палитру рига, чем бы она ни генерилась
    wallpaper             # симлинк на текущие обои
    accent-key            # строка: имя ключа акцента внутри palette.json
  logo.svg
  animations-runtime.lua  # чанк анимаций для горячего свитча
  hypr/                   # конфиг композитора (как сейчас)
```

Тогда:

- `rigdo <действие>` = «запустить `profiles/active/actions/<действие>`, если он
  есть, иначе показать hint». Двадцать семь ветвлений схлопываются в одну
  строку.
- `Palettes.qml`, `kbd-theme-sync`, `rig-theme` читают `theme/palette.json` по
  фиксированному пути вместо того, чтобы каждый по-своему знать, где у какого
  рига палитра.
- Свитчер берёт `logo.svg` и `role` оттуда же и про риги ничего не знает.

### Почему соглашение, а не манифест (`rig.toml`)

Рассматривался и манифест — один файл с описанием. Отвергнут по двум причинам.

Действия рига не всегда одна команда: рестарт шелла caelestia — это `kill`,
затем `-d`; скретчпады содержат условие с проверкой класса окна. В манифесте
такое превращается в скрипт, записанный внутри строки с экранированием. Файл
`actions/shell` — просто скрипт, его видно и можно запустить руками.

И не нужен парсер: bash проверяет `-x`, QML читает JSON по фиксированному пути.
Ни `jq`, ни TOML-библиотеки в зависимостях.

## Что это даёт

Добавить риг = положить каталог. **Ни строчки в коде.** А поскольку риг больше
не обязан лежать внутри этого репозитория, свитчер отделяется от дотфайлов и
становится тем, чем хочется — самостоятельным проектом, которому дают ссылку на
каталог.

Побочно: `dotprofile doctor` начинает проверять контракт целиком — есть ли
`actions/`, не битые ли симлинки в `theme/`.

## Цена и порядок

Переписываются `rigdo`, `kbd-theme-sync`, `Palettes.qml`, `rig-theme`; у обоих
существующих ригов заводятся `actions/` и `theme/`. Это трогает работающее,
поэтому по одному скрипту с проверкой после каждого.

Разумный порядок: `rigdo` (самый тяжёлый и самый заметный результат) → `theme/`
симлинки и потребители палитры → `doctor` под новый контракт → вынос свитчера в
отдельный репозиторий.

## Что решить до старта

- Где живут риги, если свитчер отдельный проект: список путей в конфиге
  пользователя? каталог с симлинками?
- Что делать с ригом, у которого нет `actions/<действие>` — молчать или
  показывать hint (сейчас hint).
- Совместимость: перевод обоих ригов разом или период, когда работают обе
  схемы.
